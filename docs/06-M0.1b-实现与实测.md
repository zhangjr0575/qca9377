### 1.1 结果

```
ath10k-bar0-length     = 2097152        ← 0x200000，BAR0 映射成功
ath10k-chip-id         = 0xFFFFFFFFDEADBEEF（实际读到 0xDEADBEEF）

```

无新增 panic，系统稳定。

### 1.2 结论：**关键地基验证通过**

| 验证点 | 结果 | 意义 |
| --- | --- | --- |
| IO80211 语境下映射 BAR0 | ✅ 成功（2MB） | **路线 A 的地基成立**，硬件可访问 |
| MMIO 读取 | ✅ 成功（无 panic） | 寄存器访问链路正常 |
| 芯片识别 | ⚠️ 读到 `0xDEADBEEF` | 哨兵值 = **芯片未唤醒**，符合预期 |

`0xDEADBEEF` 不是故障：M0.1a 刻意只读不写，芯片仍处于睡眠态，`SOC_CHIP_ID` 返回无效值属正常。

### 1.3 本次暴露的两个 bug（已修复）

| Bug | 表现 | 修复 |
| --- | --- | --- |
| OSNumber 符号扩展 | 属性显示 `0xFFFFFFFFDEADBEEF` 而非 `0xDEADBEEF` | 强制走 64 位无符号重载 + 新增 `*_hex` 字符串属性 |
| 哨兵值误判 | 把 `0xDEADBEEF` 当成"芯片版本不支持" | 新增 `isChipIdSentinel()`，正确报 `chip-id-invalid` |

第一个 bug 会直接误导判断——若没解码就下结论，会以为芯片 ID 是某个奇怪的大数。

## 二、M0.1b 实现：唤醒 + 冷复位 + 芯片识别

### 2.1 序列（对齐 Linux ath10k / Ath10kMac `probeTarget` 前段）

```
1. disableASPM()          关闭 PCIe L0s/L1，稳定复位窗口
2. readChipIdValue()      第一次读（预期哨兵）
3. wakeTarget()           写 SOC_WAKE=1，轮询 RTC_STATE 直到 == RTC_STATE_V_ON(3)
                          超时 30ms，退避步进 5→50us
4. coldResetTarget()      SOC_GLOBAL_RESET |= 1，IOSleep(20ms)，&~1，IOSleep(20ms)
5. wakeTarget()           复位后重新唤醒
6. readChipIdValue()      第二次读（预期有效）
7. releaseTargetWake()    释放 SOC_WAKE
8. restoreASPM()          恢复原 ASPM 配置
```

### 2.2 新增诊断属性

| 属性 | 含义 | 期望值 |
| --- | --- | --- |
| `ath10k-aspm-disabled` | ASPM 是否关闭 | 1 |
| `ath10k-wake-ok` | 唤醒是否成功 | 1 |
| `ath10k-wake-delay-us` | 唤醒耗时 | 通常 < 20000 |
| `ath10k-rtc-state-before` | 唤醒前 RTC_STATE | 0x00000000 |
| `ath10k-rtc-state-after` | 唤醒后 RTC_STATE | **0x00000003** |
| `ath10k-cold-reset-done` | 冷复位是否完成 | 1 |
| `ath10k-global-reset-before/after` | SOC_GLOBAL_RESET 前后值 | after 最低位 = 0 |
| `ath10k-pcie-link-control-before/after` | Link Control | after & 0x3 == 0 |
| `ath10k-chip-id-hex` | 芯片 ID 十六进制 | 有效值时便于判读 |
| `ath10k-chip-id-attempts` | 读取尝试次数 | 已唤醒则 1，否则 2 |

### 2.3 判读路径

| `ath10k-hardware-status` | 含义 | 下一步 |
| --- | --- | --- |
| `ok` | 芯片唤醒并识别 | 进入 M0.1c：BMI 固件下载 |
| `wake-failed` | SOC_WAKE 后 RTC_STATE 未到 3 | 需补 PCIe bring-up parity（MSI/中断配置） |
| `cold-reset-failed` | 写 SOC_GLOBAL_RESET 失败 | 检查 BAR0 写权限 / 寄存器布局 |
| `rewake-failed` | 复位后无法再次唤醒 | 复位时序需对齐 Linux（延迟/顺序） |
| `chip-id-invalid` | 唤醒复位后仍读到哨兵 | 检查 RTC_STATE 实际值，可能需 CPU 唤醒步骤 |

## 三、安全性

M0.1b 只操作三类寄存器：
- PCIe Link Control（ASPM，操作后恢复原值）
- PCIE_LOCAL 的 RTC_STATE / SOC_WAKE / SOC_GLOBAL_RESET
- RTC_SOC 的 SOC_CHIP_ID（只读）

**不触碰** CE ring、DMA、MSI 中断、固件区——这些属 M0.1c，风险更高，需单独里程碑。
