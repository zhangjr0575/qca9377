# QCA9377 原生 WiFi（AirPort）编码计划

> 本计划基于《01-调研报告.md》。确认后进入编码。所有阶段均以“可运行增量”交付，任何一阶段未达标即回滚到上一里程碑。

## 0. 技术路线

**路线 A**：新增 `Ath10kHal : ItlHalService`，把 Ath10kMac 的硬件/MAC 能力映射为 net80211 驱动回调；复用 itlwm 的 AirportItlwm 控制器层 + net80211，产出 `AirportAth10k.kext`。

```
AirportAth10k : IO80211Controller   ← 由 AirportItlwm 改名/改造而来（复用）
    → ieee80211com (net80211)        ← 复用
        → Ath10kHal : ItlHalService  ← 新增（移植 ath10k 到 net80211）
            → Ath10kMac 硬件原语（PCI/CE/DMA/BMI/HTC/WMI/HTT）← 复用
```

---

## 1. 目标与范围

### 1.1 首版目标（对齐 Ath10kMac 已验证能力 + AirportItlwm 能力边界）
- 原生扫描：2.4/5 GHz 非 DFS 信道网络出现在系统 Wi-Fi 菜单。
- 原生连接：开放网络、WPA2-PSK（CCMP pairwise，CCMP/TKIP group）。
- 数据面：DHCP + 双向流量。
- 断开/重连、睡眠唤醒后的重连。
- 显式不支持：WPA3/SAE、强制 PMF、TKIP pairwise、DFS、AirDrop/AWDL、AP 模式（与 AirportItlwm 现状一致）。

### 1.2 明确不做（本阶段）
- 不修改 Ath10kMac 现有以太网式驱动本身（保持其可用作回退基线）。
- 不改动 net80211 与 AirportItlwm 控制器层的既有行为逻辑（只做改名/板卡匹配/构建集成）。

## 2. 里程碑划分

| 里程碑 | 目标 | 验收标准 |
| --- | --- | --- |
| M0 | 工程骨架 + 固件启动 | kext 加载、匹配 `168c:0042`、固件下载、MAC 地址读回、发布 AirPort 接口 |

## 3. 各里程碑任务分解

### M0 — 工程骨架 + 固件启动
**目标**：证明“ath10k 硬件能挂到 net80211 驱动骨架下并启动固件”。

任务：
1. 在 `itlwm.xcodeproj` 新建 target `AirportAth10k-Sequoia` / `AirportAth10k-Tahoe`（复制 AirportItlwm 两个 target 的 build settings，替换 Info.plist 的 PCI 匹配为 `168c:0042`）。
2. 新建 `itlwm/itlwm/hal_ath10k/Ath10kHal.hpp/.cpp`，实现 `ItlHalService` 接口骨架（`attach/detach/enable/disable/get80211Controller/getDriverInfo/getDriverController`），其中 `get80211Controller()` 返回一个已初始化的 `ieee80211com`。
3. 将 Ath10kMac 的硬件 bring-up 原语（PCI/CE/DMA/BMI/HTC/WMI 启动、payload 选择）引入或复用，使 `attach()` 完成固件下载与芯片复位、读回 MAC。
4. 把 `Ath10kPayload.hpp` 生成逻辑接入新 target（沿用 `scripts/prepare-firmware.py`，勿手改生成文件）。
5. 单元/构建验证：`make`/`xcodebuild` 通过，kext 符号检查通过。

**涉及文件（新增/修改）**
- 新增：`itlwm/itlwm/hal_ath10k/Ath10kHal.hpp`、`Ath10kHal.cpp`
- 新增：`itlwm/AirportItlwm/Ath10k-Info.plist`（或沿用并改 PCI 匹配）
- 修改：`itlwm/itlwm.xcodeproj/project.pbxproj`（新 target/scheme）
- 复用：Ath10kMac `src/kext/*` 硬件文件、`Ath10kPayload.hpp`

**验收**：`AirportAth10k.kext` 在目标机加载，日志显示固件启动、MAC 回读，`ifconfig`/系统信息中出现 Wi-Fi 接口。

### M1 — 原生扫描
**目标**：让 net80211 的扫描结果能被 WMI 扫描事件填充。

任务：
1. 实现 net80211 扫描回调：将 net80211 的扫描请求映射为 ath10k WMI start-scan 命令。
2. 实现 WMI scan 事件解析，把 beacon/probe 结果转成 net80211 的 `ieee80211_node` / 扫描结果。
3. 复用 Ath10kMac 的 5 GHz DS Parameter Set 修复与快速首扫逻辑（见其 README 已修复项）。
4. 接入 AirportItlwm 的 `SCAN_REQ`/`SCAN_RESULT` ioctl（复用控制器层，无需新写）。

**验收**：系统 Wi-Fi 菜单展示真实网络列表，RSSI 正确。

### M2 — 开放网络连接
**目标**：打通 `ic_newstate` 的 AUTH→ASSOC→RUN，完成开放网络数据面。

任务：
1. 实现 `ic_newstate`：AUTH/ASSOC 阶段复用 Ath10kMac 的 WMI mgmt 帧构建（Auth/Assoc 帧），peer 创建/删除。
2. 实现数据面 tx/rx：`outputPacket` → HTT TX；HTT RX → net80211 输入。
3. 处理 beacon/连接事件，驱动 net80211 状态到 `RUN`、链路状态置 UP。
4. 实现断开/去关联清理路径。

**验收**：原生连接开放网络，DHCP 取址，ping/HTTP 双向通。

### M3 — WPA2 + Apple RSN
**目标**：Apple Supplicant 完成四次握手，密钥经 WMI 下发。

任务：
1. 保持 `useAppleRSNSupplicant() = true`；移除/绕过 Ath10kMac 内置 Supplicant。
2. 实现 `ic_set_key`/`ic_delete_key` → 复用 Ath10kMac `buildSecurityWMI`（WMI 0x5009 安装/关闭），处理 pairwise PTK 与 group GTK（含 TKIP group 的 MIC key 交换，沿用 Ath10kMac 已验证逻辑）。
3. 衔接 Apple `setPTK`/`setGTK` 时序（复用 AirportItlwm 既有代码路径），确保 peer 先创建、密码套件匹配。
4. 处理组密钥更新/重放保护。

**验收**：原生连接 WPA2-PSK（CCMP；混合 TKIP group），DHCP + 双向流量稳定。

### M4 — 打磨与回归
**目标**：达到与 Ath10kMac 已验证能力对等的质量。

任务：
1. HT/VHT 协商、AMPDU 收发（`ic_ampdu_*` 回调）。
2. 断开/重连、睡眠唤醒重连。
3. 回归测试：复用/移植 Ath10kMac `tests/`（QCA9377 识别、WPA2 套件解析、密钥安装、scan 事件解析等），新增 net80211 层单测。
4. 文档：README、OpenCore 注入说明、能力边界表。

**验收**：在目标机（Sequoia/Tahoe）上完成扫描/连接/流量/重连/唤醒全套回归，测试脚本通过。

## 4. 构建与测试方法

- 构建：`xcodebuild -project itlwm.xcodeproj -scheme AirportAth10k-<Sequoia|Tahoe> -configuration Release ARCHS=x86_64 CODE_SIGNING_ALLOWED=NO build`（与 itlwm 一致）。
- 单测：沿用 Ath10kMac 的 `tests/` 框架（mock_iolib），为新增回调补测。
- 真机：USB EFI 注入 `AirportAth10k.kext`，`sudo sh scripts/test-runtime.sh` 采样诊断（先备份可用 EFI，不直接替换内置 EFI）。
- 日志：verbose/debug 启动参数下抓内核日志，定位扫描/认证/密钥/数据面问题。

## 5. 风险与回滚

- 每个里程碑产出独立可运行 kext；未达验收即回滚到上一里程碑。
- 保留 Ath10kMac 现有驱动作为回退基线（不破坏）。
- net80211 移植中的语义差异（扫描/assoc/密钥生命周期/AMPDU）是主要风险，M1/M3 是高风险里程碑，需真机反复验证。
- Apple RSN 与 WMI 密钥时序若在 M3 受阻，备选：先以内置 Supplicant 打通 WPA2（退化为“原生界面 + 驱动握手”），再切 Apple Supplicant。
