# M1-b2 实现说明：WMI INIT + host memory + vdev create

> 状态：**已真机验证通过（2026-11-16 22:46）**
> 最后更新：2026-11-16 22:20
> 对应代码：`itlwm/itlwm/hal_ath10k/Ath10kHal.cpp`、`hw/Ath10kWmiTlv.hpp`
> 验证脚本：`scripts/verify-m1b2.sh`、`tests/wmi-tlv-selftest.cpp`（离线自测）

---

## 一、目标

在 M1-b1（收到 WMI 事件、服务协商完成）之后，把固件推进到"可以建 vdev"的状态：

1. 等 `SERVICE_READY(1)`，取固件 ABI、RF 链数、host memory 请求、服务位图；
2. 按请求分配 host memory DMA 块；
3. 经 CE3 发 `WMI INIT`，经 CE2 等 `READY(2)`，从里面取 **target MAC**；
4. 经 CE3 发 `VDEV_CREATE`（STA 模式）；
5. 把真实 MAC 写回 net80211（`ic_myaddr` + `if_setlladdr`），替换占位 MAC。

## 二、关键 ABI（Linux v6.12 `wmi-tlv.h`，已与真机核对）

### 2.1 事件顺序

| ID | 名称 | 作用 |
| --- | --- | --- |
| 3 | `WMI_TLV_SERVICE_AVAILABLE_EVENTID` | 服务可用性位图。**紧邻 SERVICE_READY 之前**发出 |
| 1 | `WMI_TLV_SERVICE_READY_EVENTID` | 固件 ABI / RF 链数 / host memory 请求 / 完整服务位图 / 射频能力 |
| 2 | `WMI_TLV_READY_EVENTID` | 对 `WMI INIT` 的响应，带 target MAC 与状态字 |

> 重要：M1-b1 当初只收到事件 3 就宣布成功，这是**误判**。事件 3 只是可用性位图，
> 真正的 `SERVICE_READY` 是事件 1。本阶段已把 bootstrap 的完成条件改成"收到事件 1"，
> `ath10k-wmi-service-ready` 的语义也随之改变（见第六节）。

### 2.2 TLV tag（`enum wmi_tlv_tag`，已逐个核对数值）

| tag | 名称 | 出现位置 |
| --- | --- | --- |
| 16 | `ARRAY_UINT32` | 事件 1：服务位图，长度必须 128 字节（1024 位） |
| 18 | `ARRAY_STRUCT` | 事件 1：host memory 请求数组；INIT 命令：chunk 数组 |
| 32 | `STRUCT_SERVICE_READY_EVENT` | 事件 1，最小 104 字节 |
| 33 | `STRUCT_HAL_REG_CAPABILITIES` | 事件 1，最小 36 字节（9 字） |
| 34 | `STRUCT_WLAN_HOST_MEM_REQ` | 每个 host memory 请求（20 字节一条） |
| 35 | `STRUCT_READY_EVENT` | 事件 2，最小 36 字节 |
| 74 | `STRUCT_INIT_CMD` | INIT 命令，28 字节 |
| 75 | `STRUCT_RESOURCE_CONFIG` | INIT 命令，176 字节（44 字） |
| 76 | `STRUCT_WLAN_HOST_MEMORY_CHUNK` | INIT 命令，16 字节/块 |
| 86 | `STRUCT_VDEV_CREATE_CMD` | vdev create，20 字节 |
| 559 (`0x22f`) | `STRUCT_SERVICE_AVAILABLE_EVENT` | 事件 3，4 + 16 = 20 字节 |

### 2.3 事件 1 字段偏移（TLV 负载内）

```
+0    fw_build_vers
+4    abi[0..5]（6 字，24 字节）
+36   num_rf_chains        ← QCA9377 应为 1
+40   ht_cap_info
+44   vht_cap_info
+48   vht_supp_mcs
+52   hw_min_tx_power
+56   hw_max_tx_power
+72   num_mem_reqs
总长 ≥ 104
```

### 2.4 事件 2（READY）字段偏移

```
+0    abi[0..5]（24 字节）
+24   mac[0..5]（wmi_mac_addr 是 8 字节 union，30..31 为填充）
+32   status（0 = 成功）
总长 ≥ 36
```

### 2.5 WMI INIT 帧（228 + 20 × host-memory 块数）

```
偏移      内容
0         HTC endpoint（= WMI 端点 2）
1         HTC flags：bit0 = NEED_CREDIT_UPDATE
2-3       HTC payload 长度 = 总长 - 8
5         HTC 序号（WMI 端点内单调递增，INIT 用 0）
8-11      WMI_TLV_INIT_CMDID = 0x1
12-15     TLV: len=28, tag=74
16-39     host ABI 6 字 = {0x01000000, 53, 0x5f414351, 0x4c4d, 0, 0}
40-43     host memory 块数
44-47     TLV: len=176, tag=75
48-223    resource config 44 字（Linux QCA6174 默认值，链数位按固件上报改写）
224-227   TLV: len=20*n, tag=18
228+20*i  每块：TLV(16, 76) + req_id + 物理地址 + 字节数
```

`resource config` 中 `cfg[7]`/`cfg[8]` 是 TX/RX chain mask：
`(1 << min(fw_rf_chains, hardware_chains)) - 1`。QCA9377 是 1x1，所以是 `1`。
`cfg[2]`/`cfg[3]`（offload peers / reorder bufs）只在服务位 65（4ADDR）置位时改为 4。

### 2.6 VDEV_CREATE 帧（36 字节）

```
0     HTC endpoint
1     NEED_CREDIT_UPDATE
2-3   28
5     HTC 序号
8-11  0x5001（WMI_TLV_CMD(GRP_VDEV=5)）
12-15 TLV: len=20, tag=86
16-19 vdev_id = 0
20-23 type = 2（STA）
24-27 subtype = 0（NONE）
28-33 MAC（6 字节，union 占 8 字节）
```

### 2.7 CE 管道（不可动摇）

| CE | 方向 | 用途 |
| --- | --- | --- |
| CE0 / CE1 | H2T / T2H | HTC 控制端点 0（SETUP_COMPLETE、服务连接） |
| CE2 | T2H | WMI 事件/响应 |
| CE3 | H2T | WMI 命令 |

CE3 源描述符的 `flags` 字段必须写 `endpoint << 2`（QCA6174/QCA9377 的 metadata 位移）。
WMI 命令**不能**走 CE0。

## 三、实现结构

### 3.1 `hw/Ath10kWmiTlv.hpp`（新增/重写，约 540 行）

| 内容 | 说明 |
| --- | --- |
| `WMICreditState` | WMI 端点信用账本：`initialize/reserve/giveBack`，按 `creditSize` 折算 |
| `WMIHostMemoryRequest/Chunk` | host memory 请求与已分配块 |
| `hostMemoryRequestBytes` | 按 flags 推导实际块字节数（flags bit1/2 → 34 units，bit0 → 5 units） |
| `WMIEventInfo` | 一条事件的结构化解析结果（事件 1/2/3 全部字段） |
| `parseWMIEvent` | HTC 信封 + TLV + trailer 信用全量校验，整帧通过后才提交信用 |
| `buildWMIInit` | INIT 帧构造，含 host memory chunk 校验（对齐/不重叠/4 GB 内） |
| `buildWMIVdevCreate` | vdev create 帧构造，拒绝组播/全零 MAC |

### 3.2 `Ath10kHal.cpp`（新增约 480 行）

| 函数 | 作用 |
| --- | --- |
| `armWmiRx` | CE2 首次挂接收描述符（保留原有实现，增加 `wmiRxArmed` 状态） |
| `wmiRepostRx` | 收到事件后把 CE2 描述符推进到下一槽位（清旧描述符 + 清缓冲） |
| `wmiEnsureRxArmed` | 首次 arm / 后续 repost 的统一入口 |
| `wmiWaitEvent` | 轮询 CE2 → 解析事件 → 合并状态；超时/解析失败给出独立状态串 |
| `wmiApplyEvent` | 跨事件累积 SERVICE_AVAILABLE / SERVICE_READY / READY 结果 |
| `runWMIBootstrap` | SETUP_COMPLETE → 等事件 3 与事件 1（总超时 5 s，最多 24 条事件） |
| `wmiInitCredits` | 用 HTC READY 的 `credits/creditSize` 初始化 WMI 信用账本 |
| `wmiSubmitCommand` | CE3 通用命令提交：校验空闲 → 写描述符 → 预留信用 → 门铃 → 等消费 |
| `runWMIInit` | host memory 分配 + INIT + 等 READY(2) + 应用 MAC |
| `runWMIVdevCreate` | vdev create + 收事件归还信用（无语义响应） |
| `applyTargetMac` | 写回 `ic_myaddr` 并 `if_setlladdr` |

### 3.3 一次性语义（与既有约束一致）

- `wmiTxOwned` 在门铃**之前**置位；若 CE3 完成状态未知，后续命令一律拒绝（"CE3 污染"）。
- 同一上电周期内 host memory 块尺寸不一致直接失败，不重分配。
- INIT 失败不做任何回退重试。

**结论：WMI INIT 全流程通过，固件给出了真实 MAC；vdev 阶段被两个实现缺陷挡住。**

### 缺陷 1（阻塞性）：`wmiSubmitCommand` 的 CE3 污染守卫把自己拦住了

```cpp
    wmiTxConsumed = false;                       // ← 入口先清零
    ...
    if (wmiTxOwned && !wmiTxConsumed) {          // ← 第二次提交必然命中
        return false;                            //    "uncertain previous submit"
    }
```

INIT 成功提交后 `wmiTxOwned = true`，第二次（vdev）调用在入口把 `wmiTxConsumed` 清零，
守卫立刻判定"上一条未确认"，于是 vdev 命令**根本没发出去**（`vdev-wait-ms = 0`、
`vdev-tx-consumed = 0` 正好对应）。

**修复**：把清零挪到"本次提交真正接管 CE3"的时刻（预留信用成功、写门铃之前），
守卫改在清零前判断。同时新增 `ath10k-wmi-tx-fail` 逐分支标记
（`prerequisite` / `uncertain-previous` / `ce3-not-idle` / `tx-sync` / `no-credit` /
`doorbell` / `src-read` / `timeout`），失败时不会再出现"只有 timeout 一种模糊状态"。

### 缺陷 2：信用回报只在 CE2 上找，漏掉了 CE1 与纯 trailer 帧

实测 `outstanding = 1` 一直不降：INIT 用掉 1 个信用后，固件没有把归还记录挂在
CE2 的 READY / DIAG 事件里。Linux 的 HTC 里，信用报告是任意固件→主机帧的 trailer
记录，实际常从 CE1（控制端点 0）回来，也可能单独成包（无 WMI 事件头）。

**修复**：

- 新增 `htcRuntimeRepostRx()` / `htcEnsureRuntimeRx()`（对齐参考实现的
  `htcRepostRuntimeReceive`），让 CE1 始终保持一个在途描述符；
- 新增 `htcRuntimePump()`：非阻塞消费 CE1 的包，只处理 trailer 里的信用回报；
- `hw/Ath10kWmiTlv.hpp` 新增 `applyHTCCreditTrailer()`，放宽 `parseWMIEvent`
  接受"纯 trailer 帧"（`trailerOnly`）；
- 三个阶段的等待循环统一改为 `wmiPumpOnce()`（CE1 信用 + CE2 事件 + 固件心跳），
  不再用阻塞式 `wmiWaitEvent`；
- READY 之后只再等 1.5 s 信用（`kWMIInitCreditWaitMs`），避免拖慢开机。

### 缺陷 3（诊断缺口）：没有固件崩溃判定

参考实现在这些循环里读 `FW_INDICATOR`，`EVENT_PENDING` 置位即判定固件崩溃。
本轮补上 `sampleFirmwareIndicator()`：首次采样作为基线，只有**启动后新出现**该位
才判定崩溃（避免上一轮残留位造成误判），并发布 `ath10k-fw-indicator` /
`ath10k-fw-indicator-baseline` / `ath10k-firmware-crash`。

### 顺带修正：接口 MAC 仍是占位值

`ath10k-target-mac` 已正确，但 `ifconfig en4` 还是 `02:11:22:33:44:55`。
原因是 `ic_myaddr` 只在 `attach()` 时被 `ieee80211_ifattach` 拷进接口，
兼容层 `if_setlladdr()` 只写 `arpcom.ac_enaddr`，不动 BSD 侧 lladdr。

**修复**：`applyTargetMac()` 额外做一次
`ifp->iface->getIfnet()` + `ifnet_set_lladdr()` + `IOMACAddress` 属性同步
（与控制器 `setHardwareAddress` 的做法一致），失败只记录日志不阻断流程。

## 六、语义变更与兼容性说明

1. **`ath10k-wmi-service-ready` 的语义**
   - M1-b1：收到事件 3（SERVICE_AVAILABLE）即置 1。
   - M1-b2：只有收到事件 1（SERVICE_READY）才置 1；事件 3 改由
     `ath10k-wmi-service-available` 表示。
   - `ath10k-wmi-service-bits` / `ath10k-wmi-bitmap0..3` 仍然表示事件 3 的位图，含义未变。

2. **`ath10k-hardware-status` 终值**
   - 从 `wmi-service-ready` 改为 `wmi-ready`（INIT + vdev 都通过之后）。
   - 中间失败会停在 `wmi-bootstrap-failed` / `wmi-init-failed` / `wmi-vdev-failed`。

3. **MAC**
   - READY 事件给出真实 MAC 后，`ic.ic_myaddr` 与接口 lladdr 都会被更新；
     `ath10k-target-mac` 可独立于接口观测。
   - 若固件给出全零/组播 MAC，`target-mac-valid = 0`，vdev create 退回占位 MAC
     `02:11:22:33:44:55`（仍满足单播要求），并在日志中标注。

## 七、失败模式与定位

| 现象 | 原因 | 查什么 |
| --- | --- | --- |
| `wmi-status` = `wmi-service-ready-event-missing` | 只收到事件 3，事件 1 没来 | `ath10k-wmi-event-id`、`wmi-evt-prefix` |
| `wmi-status` = `wmi-event-invalid` | 事件结构/TLV 校验失败 | `ath10k-wmi-parse-error` + `wmi-evt-prefix` |
| `wmi-status` = `firmware-crash` | 启动后 `FW_INDICATOR.EVENT_PENDING` 翻转 | `ath10k-fw-indicator` / `-baseline` |
| `wmi-init-status` = `wmi-init-abi-mismatch` | 固件 ABI 与 host ABI 不符 | `wmi-abi0/abi2/abi3` |
| `wmi-init-status` = `wmi-ready-timeout` | INIT 发出但无 READY | `wmi-init-tx-bytes`、`credits-outstanding`、`wmi-evt-prefix` |
| `wmi-init-status` = `wmi-ready-firmware-rejected` | READY 状态字非 0 | `wmi-ready-status` |
| `wmi-init-status` = `wmi-host-memory-*` | host memory 请求解析/DMA 分配失败 | 控制台 `Ath10kHal: WMI host memory ...` 日志 |
| `wmi-init-status` / `vdev-status` = `no-credit` | 信用不足 | `credits-total/available/credit-size` |
| `wmi-init-status` / `vdev-status` = `ce3-not-idle` | CE3 源环读写指针不相等 | `wmi-tx-src-write` / `-src-read` |
| `wmi-init-status` / `vdev-status` = `timeout` | 门铃已提交但 CE3 未消费 | `wmi-tx-src-read` 是否停在旧值；`firmware-crash` |
| `wmi-init-status` / `vdev-status` = `uncertain-previous` | 上一条命令完成状态未知，主动拒绝重发 | `wmi-seq`、日志 `WMI TX BLOCKED` |
| `vdev-status` = `doorbell` / `tx-sync` | MMIO 或 DMA 同步失败 | 控制台 `WMI TX doorbell` / `tx-sync` |

`ath10k-wmi-tx-fail` 的取值就是上表第二列（`prerequisite` / `uncertain-previous` /
`ce3-not-idle` / `tx-sync` / `no-credit` / `doorbell` / `src-read` / `timeout`）。


## 八、与参考实现（Ath10kMac）的差异

| 项 | Ath10kMac | 本项目 | 原因 |
| --- | --- | --- | --- |
| 4ADDR 服务位判断 | `serviceBitmap[65/4] & (1 << (65%4))` | `serviceBitmap[65/32] & (1 << (65%32))` | 按 Linux `test_bit(65)` 的 32 位字索引；只有当次位确实置位才影响 `cfg[2]/cfg[3]` |
| RF 链数 | `_deviceId == kQCA9377 ? 1 : 2` | 固定 1（QCA9377 单链） | 本驱动只支持该板卡 |
| INIT 后流程 | ECHO barrier → RX setup → vdev → radio | 直接 vdev create | M1-b2 范围内不需要 ECHO/RX setup；留到 M1-c 前补 |
| vdev 语义响应 | 明确"无响应，只看传输完成" | 相同 | 固件行为一致 |
| 信用归还严格度 | 必须归还才继续 | INIT 要求 READY + 尽量等归还；vdev 只要求 TX 消费 | 避免首轮真机因信用时序误判失败，同时把状态发布出来 |
