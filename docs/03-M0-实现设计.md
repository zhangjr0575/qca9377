# M0 代码级实现设计（Ath10kHal 走通骨架）

> 本文是 M0 里程碑的代码级设计，作为《02-编码计划.md》中 M0 的细化。目标读者：接续编码的工程师（人/AI）。

## 1. M0 目标与判定

M0 只做一件事：**打通“原生 Wi-Fi 链路”的骨架**，证明 net80211 + AirportItlwm 控制器层能挂到 QCA9377 上、kext 能加载、接口能发布。

- 验收：`AirportItlwm.kext`（Sequoia target）能匹配 `168c:0042`，`Ath10kHal::attach()` 走完 net80211 附着，系统里出现一个原生 Wi-Fi 接口（占位 MAC）。
- 不做：真实固件启动、扫描、连接、数据面（M0.1~M4）。

## 2. 集成点（已核实）

| 位置 | 现状 | M0 改动 |
| --- | --- | --- |
| `AirportItlwm::probe()` | 按 `ItlIwx/ItlIwm/ItlIwn::*_match` 建 HAL | 追加 `Ath10kHal::ath10k_match` 分支（`#ifdef AIRPORT_ATH10K`） |
| `AirportItlwm::start()` | `fHalService->initWithController` → `attach(pciNub)` | 不变（HAL 多态） |
| Sequoia target | 编译 Intel HAL + `FwBinary.cpp` | 追加 `Ath10kHal.cpp`；加 `AIRPORT_ATH10K` 宏 |
| `get80211Controller()` | 返回 `&com.sc_ic` | 返回嵌入的 `struct ieee80211com ic` |

关键约束（已核实）：
1. `get80211Controller()` 在 `attach()` **之前**就被调用（`AirportItlwm::start()` L390/393/395），只写不读 → 返回成员地址即可。
2. `ifp->if_watchdog` 必须非空：控制器每 1s 定时器回调 `(*ifp->if_watchdog)(ifp)`（`watchdogAction` L441）。
3. `ieee80211_new_state` 是宏，会无条件调用 `ic->ic_newstate` → 必须非空（net80211 默认给了 `ieee80211_newstate`，M0 用我们的 stub 覆盖）。
4. `ieee80211_ifattach` 内部调用 `ieee80211_channel_init`，**要求信道表已预先填充**（否则 `ic_modecaps` 为空、接口无频段）。

## 3. net80211 附着序列（Ath10kHal::attach 必须遵守）

```
bzero(ic)
ic.ic_myaddr = 占位 MAC（M0.1 换成 OTP 回读）
ic.ic_caps / ic_htcaps / ic_sup_rates[11a/11b/11g] / ic_max_rssi / ic_ibss_chan / ic_curmode
initChannelMap()            ← 填充 ic_channels[].ic_freq/.ic_flags
ifp = &ic.ic_ac.ac_if
ifp->if_softc / if_flags / if_ioctl(=ieee80211_ioctl) / if_start / if_watchdog / if_xname
ic.ic_newstate / ic_set_key / ic_delete_key = stub
if_attach(ifp)
ieee80211_ifattach(ifp, getController())   ← 内部做 channel_init/crypto/node/proto attach
ieee80211_media_init(ifp)
```

## 4. 与 Ath10kMac 的 bring-up 映射（M0.1 待接入）

Ath10kMac 的 bring-up 是一个**延迟状态机**（`start()` 注册服务后 `thread_call` 跑 `runDeferredProbe()`），不能直接照搬。M0.1 需要把其硬件原语拆出来、以 `ItlHalService` 的命令门/工作环模型重排：

| Ath10kMac 原语 | 位置 | 迁入 Ath10kHal 的位置 |
| --- | --- | --- |
| `identifyDevice` / 读芯片版本 | `Ath10kPCIDevice.cpp` | `attach()` 开头 |
| BAR0 映射 | `mapBAR0` | `attach()`（`IOPCIDevice::mapDeviceMemoryWithIndex(0)`） |
| CE ring / DMA | `allocateCERings`/`prepareDeviceDMAMapper` | `attach()` 或 `enable()` |
| BMI 固件下载 | `Ath10kBMI.hpp`/`Ath10kBoot.hpp` | `attach()` |
| HTC 服务建立 | `runHTCServiceSetup` | `attach()` |
| WMI 引导/初始化 | `runWMIBootstrap`/`runWMIInit` | `attach()` |
| MAC 回读 | 固件 OTP 读取 | `attach()` 末尾，写回 `ic.ic_myaddr` |
| HTT RX 配置 | `serviceRxSetup`/`sampleHTTRxPool` | `attach()` 或 `enable()` |
| payload 选择 | `Ath10kPayload.hpp`（`144d:4133`） | 集成到本 kext 的固件 payload |

M0.1 的 bring-up 建议仍用**延迟线程**（`thread_call`），因为固件下载耗时、不能阻塞 `start()`；但命令门操作要落到 `ItlHalService::getMainCommandGate()`，与 ItlIwm 的中断/命令模型一致。

## 5. 里程碑回调填充矩阵

| net80211 回调 | M0（当前） | 目标里程碑 |
| --- | --- | --- |
| `ath_newstate` | 打日志 + 返回 0 | M1(SCAN)/M2(AUTH/ASSOC/RUN) |
| `ath_set_key` / `ath_delete_key` | 空返回 | M3 → `buildSecurityWMI`（WMI 0x5009） |
| `ath_start`（tx） | 清 OACTIVE | M2 → HTT TX |
| `ath_watchdog` | 空 | M4 → beacon 超时/固件看门狗 |
| 扫描事件 | 无 | M1 → WMI scan 事件 → net80211 节点 |

## 6. 构建与验证

```sh
cd itlwm
xcodebuild -project itlwm.xcodeproj -scheme AirportItlwm-Sequoia \
  -configuration Release ARCHS=x86_64 CODE_SIGNING_ALLOWED=NO \
  -derivedDataPath /tmp/itlwm-dd build
```

产物：`/tmp/itlwm-dd/Build/Products/Release/Sequoia/AirportItlwm.kext`。

- 编译期验证：`Ath10kHal.cpp` 能编译链接（`OSDefineMetaClassAndStructors` 不冲突）。
- 运行期验证（需真机/黑苹果）：kext 加载、日志出现 `Ath10kHal: M0 walking skeleton attached`、`ifconfig`/系统信息出现 Wi-Fi 接口。
- 已知 M0 边界：占位 MAC、无真实扫描结果、无连接能力；接口仅“可见”。

## 7. 已知风险与后续

1. **占位 MAC 导致接口标识不稳定**：M0.1 必须换成 OTP 回读 MAC，否则不同重启间 MAC 可能不一致（本骨架用了固定占位值，反而稳定，但可能撞车）。
2. **自动扫描**：接口发布后 macOS 会尝试扫描；M0 的 `ath_newstate` stub 返回 0，net80211 会走“软件空转”而无结果，属预期行为，不崩溃即可。
3. **pbxproj 后续变更**：真正接入 Ath10kMac 硬件文件后，Sources 阶段还要追加大量 `.cpp`，建议届时改为独立 `AirportAth10k-Sequoia` target 以与 Intel 驱动隔离。
